Both rules from `rules.ini` and types INI files (e.x. `units.ini`) are exposed to Lua scripts to allow changing rules. 

## Rules API

- The [common/lua/rules_luaapi.h](../../common/lua/rules_luaapi.h) file contains the `RulesLuaApi` class
- This class provides the following Lua functions:
    - `getSectionNames` gets all sections in `rules.ini`
    - `getRuleNamesForSection` gets all rules in a section
    - `getRuleValue` get the current value for rule (from a `RulesSection` instance)
    - `setRuleValue` sets the value for a rule (updating a `RulesSection` instance)
- A wrapper around these functions is provided by the native Lua API [Rules](../../common/lua/scripts/nco/Rules.lua)
  - This uses the [RulesApiProxy](../../common/lua/scripts/nco/lib/RulesApiProxy.lua) class to allow accessing sections and rules using Lua table keys
- The `RulesSection` instance is intended to be provided by a class which follows the C++ concept `RuleSectionsProviderConcept`

## Tiberian Dawn

- [tiberiandawn/lua/scenariolua.h](../../tiberiandawn/lua/scenariolua.h) defines the `TdRuleSectionsProvider` static class
- This class implements the `RuleSectionsProviderConcept` C++ concept
  - It provides access to the `Sections` field of the `Rule` global instance of `RulesClass`
  - This field is initialised by `RulesClass` with the `rules.ini` values, falling back to hardcoded defaults
- When registering the `RulesLuaApi` API with the Lua Engine, this class is passed as a template parameter

### Types API

- The [tiberiandawn/lua/tdtypes_luaapi.h](../../tiberiandawn/lua/tdtypes_luaapi.h) file contains the `TiberianDawnTypesLuaApi` class
- For each type currently supported by the rules API, this class provides the following Lua functions (replacing `<TYPE>` with `Infantry`, `Unit` etc.):
  - `get<TYPE>InstanceNames` gets all type instances as strings (the sections in the INI file, e.x. `unit.ini`)
  - `get<TYPE>PropertyNames` gets all valid properties for the type (rules in the INI section)
  - `get<TYPE>PropertyType` gets the type for a given type property (`number`/`bool`/`string` or a C++ type, e.x. `WeaponType`)
  - `get<TYPE>PropertyValue` for a given type instance, get the current value for a property 
  - `set<TYPE>PropertyValue` for a given type instance, set the current value for a property
- This uses the `TdTypeConverter` class to determine if a property requires string conversion to/from a C++ type
  - The `TdTypeConverter::Rule_Requires_Converter` method checks the registered types, populated by `IniRuleContext` when rules are loaded from an INI file or defaults
- The `RulesClass::TypeRules` static member is used to get rules for a given type instance using a `RulesSections` instance (A `RulesSections` instance per type, containing a `RuleSection` instance per instance)
- A wrapper around the `TiberianDawnTypesLuaApi` functions is provided by the native Lua API [Types](../../tiberiandawn/lua/scripts/nco/TiberianDawn/Types.lua)
  - This uses the [TypeApiProxy](../../tiberiandawn/lua/scripts/nco/TiberianDawn/lib/TypeApiProxy.lua) class to allow accessing types, instances and rules using Lua table keys
